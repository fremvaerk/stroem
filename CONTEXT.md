# Strøm — Domain Vocabulary

Terms used in code, specs and CLAUDE.md. CLAUDE.md holds how things work; this file
holds what the words mean. Keep both in sync when a term is added or sharpened.

- **Job** — one execution of a task; owns a set of step rows.
- **Step** — one row of a job; moves `pending → ready → claimed → running → {completed, failed, skipped, cancelled}` (or `suspended` for approval gates).
- **Step cascade** — the fixpoint that moves a job's non-running steps after a change: rollup and sequential advance of loops, promotion, cascade-skip, skip-unreachable, placeholder retirement and expansion. Implemented once in `crates/stroem-server/src/cascade.rs` (`run` pure, `apply` in one transaction, `execute` the entry point).
- **Placeholder** — the `for_each` step row that stands in for its instances; `for_each_expr` is set.
- **Instance** — a row created by expanding a placeholder: `name[i]`, `loop_source = name`, `loop_index = i`.
- **Retirement** — a placeholder leaving `pending` without expanding (skipped or failed).
- **Adoption** — a `pending` placeholder whose instances already exist being moved to `running` without re-expanding.
- **Rollup** — a `running` placeholder becoming `completed` (array of instance outputs) or `failed` once every instance is terminal.
- **Plan** — the ordered list of changes one cascade `run` produced.
- **Change** — one state transition the cascade wants applied (`Promote`, `Skip`, `Fail`, `Expand`, `Adopt`, `Rollup`).
- **Guard miss** — an apply statement that affected fewer rows than the plan named; the plan is rolled back and re-run.
- **Settlement** — deciding a job's terminal status from its steps once every step is terminal: any uncaught `failed` row (see *Caught failure*) → `failed`; else any `cancelled` → `cancelled`; else `completed` with the aggregated output of the flow steps nothing depends on. Skipped rows never decide job status, whatever their reason. Implemented in `crates/stroem-server/src/settlement/` (`settle::decide` pure, `settle_if_all_terminal` the write).
- **Dependency gate** — the rule deciding whether a step may run. `depends_on` is a tree of `{step, accept}` leaves plus `all`/`any` groups (a flat list is an implicit `all`); each leaf names which of its dependency's five terminal **outcomes** — `completed`, `failed`, `cancelled`, `skipped` (the dependency's own `when`/empty-`for_each` choice), `omitted` (the dependency was itself blocked by its own tree — unifies the old `cascade`/`unreachable` skip reasons, since nothing downstream can tell a choice-block from a failure-block several hops back) — satisfy that edge; a bare name is sugar for `accept: [completed]`, `accept: any` means all five. The gate waits for every step named anywhere in the tree to go terminal, then evaluates the whole tree once (no fail-fast on a hard block, no short-circuiting an already-satisfied `any`). Implemented in `stroem_common::{depends_on, gate}` (`DependsOnEntry`, `AcceptSet`, `Outcome`, `DepOutcome`, `gate`), shared by the server cascade and `stroem run`. Spec `docs/superpowers/specs/2026-10-01-dependency-conditions-design.md` (supersedes `2026-09-26-dependency-gate-design.md`).
- **Caught failure** — a failed step whose *own* flow step carries `continue_on_failure: true`: a direct per-step flag check, not a structural graph walk over downstream steps. Such a failure does not fail the job, and is reported as `tolerated` in `hook.failed_steps`. This is purely an accounting question (does the job still count as succeeded) and is independent of readiness (does anything downstream get to run) — that's the *Dependency gate*'s `accept` sets, decided per edge by each dependent, not by the failing step's own flag. Computed by `settlement::settle::decide` and `settlement::hooks::build_failed_steps`.
- **Terminal handling** — the once-only side effects after a job row is terminal: propagation to the parent step, task-level retry or hooks, completion notification, log close and archive.
- **Claim** — the exactly-once gate on terminal handling: the `metrics_recorded_at` compare-and-set. Fail-closed.
- **Drain gate** — no terminal handling while a step of the job is `running` or `claimed`. Fail-open.
- **Reconcile** — finding descendants that settled at creation under a parent step that is still `running`, and advancing them. Bounded by task depth.
- **Advance** — the settlement module's one body: move a job as far as its rows allow, from cascade through terminal handling.
- **Action owner (O)** — the workspace that owns a `type: task` action: the caller's own workspace for a local action, or `step.action_workspace` for a cross-workspace action reference (`owner.action`). A `type: task` action's own `input` defaults and any secrets they reference are read from `O`.
- **Task owner (T)** — the workspace whose `tasks` config actually holds the task named by a `type: task` action's `task:` field, resolved relative to `O` (a hit in `O`'s own `tasks` first, else `workspace.task` split on the first `.`). The child job runs as `T`'s job: `T`'s files, secrets, connections, current revision, ACL and hooks. `A` (caller), `O` and `T` can be three different workspaces.
- **Provenance bucket** — which of the two upstream sources produced a value handed to a `type: task` child's connection-typed input: the caller's rendered flow-step `input:` (bucket `C`, from `A`), or the action's persisted defaults (bucket `D`, from `O`). Each bucket resolves connection names against the task's own schema, gated by its own workspace of origin — `C` falls back to `T` only if `A ≠ T`, `D` only if `O ≠ T` — so a caller-local and an owner-foreign value can appear side by side in one child's resolved input.
- **Ref** — the `ref:` written next to an action or task name (flow-step `action`, `type: task` `task`, scheduler/webhook trigger `task`): a branch, a tag or a full commit SHA of the name's owner workspace, which must be a git workspace. Templated when it contains `{{` or `{%` (see *Deferred step*). Spec `docs/superpowers/specs/2026-10-02-git-refs-design.md`.
- **Pin** — a resolved `(workspace, ref, commit)`: the ref as written plus the 40-hex commit it resolved to when the job containing the reference was created. Stored on a job (`git_ref` + `revision`) or a step (`action_ref` + `action_workspace` + `action_revision`; `task_workspace` + `task_ref` + `task_revision`). In code: `PinRef { git_ref, commit }`, with the workspace held by the row.
- **Deferred step** — a flow step whose `ref:` is a template: stored with `action_type = required_ability = 'deferred'` (no worker can claim it) and resolved, when it is `ready`, by `settlement::deferred::resolve_deferred_steps`, which writes the step's real action columns. A template that renders empty (after trim) means no ref: the step resolves as an un-ref'd one. Spec `docs/superpowers/specs/2026-10-15-templated-refs-design.md`.
- **Ref memo** — table `job_ref_pin`: the one commit each `(job, owner workspace, ref as written or rendered)` runs at for the job's whole life. Seeded with a creation's `RefMemo`, extended by deferred-step resolution, first writer wins.
- **Pinned job** — a job with `git_ref IS NOT NULL`: created in owner@ref (a ref'd `type: task` child, an inherited-pin child, a ref'd trigger's job, or a hook / task retry / re-run / restart / agent task-tool child of a pinned job). Every definition it reads comes from its one commit; its ACL folder is `job.task_folder`; its state is partitioned by the ref string; task stats leave it out.
- **Pin inheritance** — an unqualified name without `ref:` written inside a pinned config resolves at that same commit; a qualified `ws.name` without `ref:` stays live. Decided at creation and stamped on the step; dispatch never infers it from the parent job.
- **PinStore** — the replica-local store of pinned commits (`workspace/pins.rs`): a bare repo per git workspace, immutable per-commit checkouts and configs, lease-aware eviction. Separate from the default-branch watcher; one process per `pin_store.dir`.
- **Pin release** — handing a claimed step back to `ready` because its pin could not be loaded on the claiming replica in time (a transient pin error); bounded by `MAX_PIN_RELEASES` (30), never a failure or a retry attempt.
- **Redaction closure** — the jobs whose pins a job's redaction set must include: the whole job tree of every job in its source lineage (hook source, restart source, task-retry original). Bounded; a closure cut by a bound fails closed (everything masked).
- **Tail read** — the newest whole lines of a log, at most `tail_bytes` (256 KiB by default), with `truncated` (exact when `false`) and `total_bytes` (an upper bound). What every log reader gets by default.
- **Full read** — the whole log as an NDJSON stream (`?full=true`); for a finished job the in-memory union of local and archive while it fits `merge_max_bytes`/`merge_max_lines`, else one source.
- **Log source** — which source answered a read: `local`, `archive`, `merged` or `none` (`X-Stroem-Log-Source`).
- **Native value** — the value a `json` input field takes from a string that is exactly one `{{ expression }}`: the expression's JSON value (object, array, number, …), not its rendered text.
- **Last fire** — the newest job of a trigger, of any status including `skipped`. A `skipped` row proves the scheduler fired, so the Last fire is the base of the Missed run mark. The "last run" the UI shows ignores `skipped` rows.
- **Missed run** — a scheduled fire time that is later than the trigger's Last fire (the first such time is skipped when it is less than 1 second after the Last fire: the clock tolerance), at least the grace period (5 minutes) in the past, and has no job. Counted only for enabled scheduler triggers that fire on this server; only the trigger's own next run clears it.
- **Leader lease** — the `idle_session_timeout` (`leader.lease_secs`, default 30 s; every other leader timing is derived from it) carried by the session that holds the leader lock: PostgreSQL ends a leader session that has sent nothing for that long, which frees the lock even when the leader's node keeps the TCP session alive. Needs PostgreSQL ≥ 14. Spec `docs/superpowers/specs/2026-10-20-leader-stale-lock-design.md`.
- **Leader validity** — how long a replica may act as leader after its last successful ping was sent (2/3 of the lease, default 20 s): `LeaderElection::is_leader()` is false once it lapses, even if no ping has failed yet.
- **Self-release** — the leader dropping the lock because one of its leader-gated loops (scheduler, recovery, event source) has been unfit — `Stalled`, or ran and then exited (`Stopped`) — for `leader.self_release_after_secs` (default 30 s, `0` = off); it does not try to become leader again while that lasts (a `Stopped` loop lasts until the process restarts).
- **Input file** — a file given to a task through a `type: file` input field, stored once as an `input_file` row plus a blob, and used by any number of jobs through Attachments. A step reads it at a path; its content is never put into a template and never redacted. The reverse of an artifact (step → server). Spec `docs/superpowers/specs/2026-10-29-file-inputs-design.md`.
- **Upload** — storing one Input file for one `(workspace, task)` before the job exists: `POST /api/workspaces/{ws}/tasks/{task}/files`, an MCP inline object, or an Upload URL. Owned by the uploading user (none with auth off); usable by that user's direct starts of that task for `input_files.upload_ttl_secs`; an Upload no job attached by then is deleted by the retention sweep.
- **File ID** — `file_` + 32 lowercase hex, the identifier of an Input file and the value STORED for a `file` field (job input, `raw_input`, step input, hook payloads, API). Opaque, never a secret, and safe in a path by construction; the template value is a path, never the ID.
- **Safe name** — the name a step sees: the uploaded name's basename with every character outside `[A-Za-z0-9._-]` replaced by `_`, a leading `.` or `-` replaced by `_`, at most 128 bytes keeping the extension (`file_field::safe_name`). The original name stays for display and download.
- **Inputs root** — the directory under which a render places files: `{root}/{file_id}/{safe_name}`. `/inputs` in containers (Docker, pod) and in every context not rendered for a worker (cascade, dispatch, agent prompts, refs); the worker's `inputs_dir` (`{temp}/stroem-inputs-{uuid}/in`) for `runner: local`.
- **Attachment** — a `job_input_file` row: one task-level `file` field of one job bound to one Input file, written in the job's creation transaction. Accepted by exactly one rule: **A1** the caller's own Upload (direct starts only), **A2** lineage (the file is attached to the job this creation derives from: Re-run / Restart source, the retry's failed job, a `type: task` child's parent), or, for a value handed to a `file`-typed action or child field, **A3** a file already attached to this job, given as its ID or its path under this render's Inputs root.
- **Upload URL** — a single-use `{auth.base_url}/api/uploads/{token}` from the MCP tool `create_upload_url`: the token (stored as SHA-256 only) is the credential, it is used up before the body is read, and it expires after `input_files.upload_url_ttl_secs`. The resulting Upload belongs to the user who asked for the URL.
- **File grant** — what a job creation may attach besides its lineage (`input_files::FileGrant`): `Direct` (A1 allowed, for a caller-started job), `TaskChild` (A2 against the parent job) or `Indirect` (lineage only: triggers, webhooks, event sources, hooks, retries, agent task-tool children).
- **Start step** — a step a Restart begins at: the one chosen step (Restart from a step, `from_step`), or every top-level step of the source job that is `failed`, `cancelled` or unfinished (Restart failed steps, `all_failed`; unfinished rows count because a restart would carry them as `cancelled`). The start steps, the steps added to the flow since the source ran, and every step that depends on them rerun; every other step is carried over. An all-failed restart records its start steps in `job.restart_from_steps`. Spec `docs/superpowers/specs/2026-11-02-restart-failed-steps-design.md`.

See `CLAUDE.md` for how these pieces fit together (architecture, conventions, key patterns).
