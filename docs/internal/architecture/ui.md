# React UI

The React UI: pages, navigation, task tree, logs, code editing and trigger status. `CLAUDE.md` indexes this file. A `§ <Title>` reference names a `###` section in any file of `docs/internal/architecture/`.

### React UI
- Pages: Login, Dashboard, Workspaces, Workspace Detail (`/workspaces/:workspace`), Tasks, Task Detail, Jobs, Job Detail, Workers, Users, Settings, plus a `*` Not Found page.
- Auth-aware, SPA with react-router, embedded via rust-embed
- **Workspace is a navigation level**: every workspace name in the UI links to `/workspaces/<name>` (Workspaces list, Tasks page badges/group rows, job header). Task Detail's back arrow goes to the workspace page. Breadcrumbs come from the pure `lib/breadcrumbs.ts::buildBreadcrumbs`, which drops the `tasks` segment of `/workspaces/:ws/tasks/:name` so every crumb links to a real route — keep it in sync when adding nested routes.
- **Task tree**: `components/task-tree.tsx` (`<TaskTree>`) renders the collapsible folder tree used by both the Tasks page and the workspace page; row building lives in the React-free `lib/task-tree.ts::buildRows` (unit-tested). Folder expansion keys are workspace-qualified (`ws::path`) only in grouped mode; workspace groups are open by default (inverted `collapsed` set). localStorage keys: `stroem_tasks_view` (`merged`|`workspace`), `stroem_tasks_expanded_folders`, `stroem_tasks_collapsed_workspaces`. The Merged/By-workspace toggle only renders when tasks span >1 workspace.
- **Log timestamps** (`lib/log-time.ts`, unit-tested): local `HH:MM:SS` like every other UI time — the log viewer used to be the one UTC outlier (`toISOString`). Elapsed mode anchors each line on the latest attempt start at or before it (`attemptStarts`: `retry_history[].started_at` + `started_at`, since a retry resets `started_at`), else the first one; negative values (worker clock behind the server's) are shown, not clamped. `attemptStarts` is empty for `action_type: agent` — a resume re-claims the step and overwrites `started_at` with no `retry_history` entry (keeping it would change the step-timeout sweep, which measures from `started_at`). `LogViewer` hides the Clock/Elapsed switch without `attemptStarts` (the `_server` panel, agent steps). localStorage key: `stroem_log_time_mode`.
- Vitest: `vitest.setup.ts` installs an in-memory `localStorage` because Node 22+'s experimental global shadows jsdom's and is `undefined` without `--localstorage-file`.
- **Tailwind v4 CSS-variable classes**: write `h-(--cell-size)` / `w-(--radix-popover-trigger-width)`, never the v3 shorthand `h-[--cell-size]` — v4 compiles that to the invalid declaration `height: --cell-size`, silently (shadcn snippets from v3-era docs carry it). Check the built CSS, not just the class list.
- **Date inputs**: `date` / `datetime` task fields render `components/task/date-input.tsx` — a typeable ISO `YYYY-MM-DD` box (parser `lib/iso-date.ts::parseIsoDate`) plus a dropdown-caption `Calendar`. Invalid text emits `""` and sets `setCustomValidity`, so the native Run form refuses to submit.
- **Syntax highlighting**: one grammar per language, two renderers. Read-only (`components/highlighted-code.tsx`, inside a caller-styled `<pre>`: job/step input/output via `JsonViewer`, the `json` field's default/replay views) walks the lezer parser from `lib/code-language.ts` with `highlightCode` — eager, chunk `vendor-lezer`, plain text above `HIGHLIGHT_MAX_CHARS` (200 000, bounds the parse) or `HIGHLIGHT_MAX_SEGMENTS` (20 000 styled spans, bounds the DOM — a long array of short numbers is ~1 span per character). Editing (`components/code-editor.tsx`) lazy-loads CodeMirror 6 (`code-editor-impl.tsx`, its own chunk, never in the initial `index.html`); the fallback while it loads, and forever if the chunk 404s after an upgrade (`lib/lazy-fallback.ts::importOr`), is a plain textarea with the same props. Suspense resolving REMOUNTS the field, so `CodeEditor` owns a `handoffRef`: the textarea's layout-effect cleanup (runs before React removes it, while it still has focus) records focus + selection, and whichever editor mounts next takes it. CodeMirror's effect cleanup hands off the same way — StrictMode's development replay destroys the first view right after it took focus (`main.tsx` mounts under `StrictMode`; a production-build Playwright run cannot see this, run the e2e focus test with `BASE_URL=http://localhost:5173` too). Prop changes (`id`, `labelId`, `language`, `placeholder`, `rows`) reconfigure the view through a `Compartment`, never recreate it (that would drop focus, selection and undo history). Both use lezer's `classHighlighter`, so every language emits the same `tok-*` classes, coloured once in `index.css` (`--tok-*` vars; `.code-dark` forces the dark palette on an always-dark panel). New language: add it to the `CodeLanguage` union — the parser map and the editor's `languageSupport` map are both `Record<CodeLanguage, …>`, so the compiler names what is missing. CodeMirror's editable element is a div: label it with `labelId` (`aria-labelledby`), not `<label for>`. Vitest drives the editor through `EditorView.findFromDOM(el).dispatch(...)`; `vitest.setup.ts` stubs the `Range` rects jsdom lacks.
- `ui/src/lib/api.ts` — token management. `ui/src/hooks/use-step-log.ts` — step log polling, full-log load and stitching (`lib/log-tail.ts::appendTail`). Its ordering rules live in the pure, unit-tested `lib/step-log-state.ts`: one never-reset request sequence; the full view is the newest snapshot plus every tail requested after it, folded in request order; an empty untruncated tail (cold replica) carries no information; polls time out after 30 s, full loads after 60 s without progress, and a pending-tail cap (64 entries / 8 MiB) abandons the oldest in-flight request. Change a race there with a model test first — five review rounds went into these interleavings.
- **Trigger run status UI**: `components/trigger-run-status.tsx` (`LastRunCell`, `MissedRunsPill`, `MissedRunsWarning`) renders the "Last run" column and warning box on the workspace page and the same pill on the task page; `components/triggers-attention-card.tsx` (`TriggersAttentionCard`) is the Dashboard card "Triggers that need attention", with its own 30 s poll, hidden when empty and on error; pure helpers in `lib/trigger-status.ts`, colours in `lib/status-styles.ts`.
